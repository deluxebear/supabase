## Fleet 职责边界

### 必须由 Fleet Control / Agent 实现

1. 项目 Attach/Detach、管理目标绑定、Agent enrollment、证书轮换与吊销。
2. 项目 endpoint registry：内部地址、公网地址、REST/Auth/Storage/Realtime/Functions/S3/DB/Pooler endpoints。
3. Connection revision：直接连接、Supavisor transaction/session profiles、TLS mode、CA reference、只读连接。
4. Desired-state 配置与 ownership：Auth/PostgREST/Storage/Realtime/runtime config 的 owner、revision、CAS、drift。
5. 异步 operation：幂等键、排队、执行、超时、取消、evidence、审计和最终状态。
6. Agent liveness 与 capability TTL：Target/Agent/Data Plane 分层健康，过期自动失效。
7. 数据库运维：密码轮换、SSL enforcement、网络策略、连接池、容量、磁盘、服务版本、升级计划。
8. Backup/PITR：inventory、policy、run、retention、restore plan、AAL2/确认、进度、失败恢复。
9. Edge Functions：secrets、artifact、deploy、probe、revision、rollback。
10. Logs/Metrics/Usage：项目隔离的查询代理、聚合、保留期和不可用降级。
11. Public API/JWT/S3 credential lifecycle：创建、轮换、吊销、只显示一次、审计。
12. 多项目隔离与状态投影：任何请求都按 org/project/target/binding/capability 约束。

### 应继续复用每个项目自己的服务

1. pg-meta：SQL、Schema、表、函数、触发器、类型、索引、扩展、角色、策略、迁移、lint。
2. Auth API：用户列表和项目 Auth 配置读写；Fleet 只负责需要跨主机重启/落盘的 reconciliation。
3. Storage API：bucket/object/policy 与常规 Storage config。
4. Realtime API：Inspector、channel policy、常规 runtime config。
5. PostgREST/Data API：schema/docs 与数据库内配置。
6. Functions runtime：运行函数；Fleet 负责部署、密钥、探针和回滚，不代理每次业务调用。

### Fleet 默认应隐藏而非实现的 Supabase Cloud 功能

1. Stripe Billing、发票、支付方式、税号、spend cap、按小时 compute 价格。
2. Dedicated IPv4 add-on、Cloud region availability、Cloud compute SKU。
3. Hosted incident status、Usercentrics、Hosted telemetry/feature flags。
4. GitHub/Vercel Marketplace、AWS PrivateLink，除非另立产品 Epic。
5. Storage Analytics/Vectors 的 Pro/region entitlement。
6. Cloud SSO/plan entitlement、Cloud preview branching、ETL Replication，除非 capability 明确 available。

## Fleet 开发优先级建议

### P0 — 先让现有管理平台“可信可用”

1. 修复 Agent heartbeat/capability TTL 与 UI 状态语义。
2. 修复 Backup status 请求的 Authorization 传播。
3. 建立 endpoint registry，消除所有 Docker 内网地址泄漏。
4. 实现 Supavisor/connection profile API，使 Connect 面板可生成连接串。
5. 用 Fleet Attach Wizard 替换 Cloud New Project。
6. 按 deployment profile 隐藏 Billing、Cloud add-ons、Hosted integrations。

### P1 — 运维闭环

1. Backup inventory/policy/run/restore/PITR。
2. Runtime desired state、ownership、CAS、drift、evidence。
3. Edge Function secrets/deploy/probe/rollback。
4. SSL、网络策略、密码轮换、pooler 配置。
5. Disk/capacity/service version/upgrade inventory 与 operation。

### P2 — 可观测性与扩展能力

1. Logs/metrics/usage aggregation 与 log drains。
2. API/JWT/S3 credential lifecycle。
3. 自定义域、HA/replica topology、branching、ETL replication（按产品范围选择）。

## 最小验收场景

1. 附加两个独立 Supabase stack，所有 URL/凭据/状态严格按项目隔离。
2. 停止一个 Agent 后 30–60 秒内 capability 降为 stale/unavailable，另一个项目不受影响。
3. Connect 面板可复制 direct、transaction、session 三类真实可用连接串。
4. 修改 runtime config 产生 operation，Agent 执行后 revision/evidence 一致；旧 revision 写入返回冲突。
5. 创建备份、展示 inventory、生成 restore plan；未通过 AAL2/精确确认不得执行恢复。
6. 部署函数、探针失败自动回滚，Studio 显示前后 revision 与日志。
7. 停止被管项目后，平台身份、组织、项目注册与审计仍可访问；项目状态准确降级。
8. 任一项目的数据库密码、service role、JWT secret、S3 secret 不出现在日志、API 列表或其他项目响应中。

### 建议的核心资源模型

1. `management_targets`：trust domain、domain endpoints、contract versions、target health。
2. `management_bindings`：org/project/target/execution target/deployment kind/capability prefixes。
3. `agent_sessions`：agent identity、certificate revision、protocol/build、last seen、lease expiry。
4. `capability_observations`：name、state、mode、source、revision、observed_at、valid_until、blockers。
5. `project_connection_revisions`：endpoints、TLS refs、secret refs、revision、observed/applied state。
6. `configuration_ownership` 与 `desired_state_revisions`：field owner、CAS token、desired/observed hash、drift。
7. `operations`、`operation_attempts`、`operation_evidence`：幂等、状态机、执行日志和结果。
8. `backup_inventory`、`backup_policies`、`restore_plans`：仅存元数据与 secret reference，不存明文凭据。
9. `function_revisions`、`function_deployments`：artifact digest、runtime config revision、probe/rollback evidence。
10. `metric_sources`、`log_sources`、`usage_rollups`：project-scoped source registration 与保留策略。

### 建议的状态推导规则

1. `Target available` 只表示管理 domain 可访问，不能推出 Agent online。
2. `Agent online` 必须满足 `now < lease_expires_at`；过期立即变为 stale，再按 grace period 变 unavailable。
3. `Capability available` 必须同时满足 observation 未过期、binding prefix 允许、target domain 可用和必要 secret reference 已配置。
4. `Data plane healthy` 来自项目服务探针，不应被 Agent/Target 故障覆盖。
5. 所有 UI mutation 必须先读取 capability + blocker；后端仍需再次授权，不能只依赖按钮禁用。
